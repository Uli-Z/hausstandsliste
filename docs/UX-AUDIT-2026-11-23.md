# Browser and UX review — 23 November 2026

**Scope:** The current V3 Svelte interface at master commit `9bd6edf`. A dedicated, request-triggered GitHub Actions run produced **32 actual Chromium screenshots**: a 1280 px desktop viewport and a 375 px mobile viewport for overview, inventory, people, money/settlement, activity, saving/sharing, settings, item detail, person detail, five primary dialogs and additional lower-screen states. The captured state used fictitious participants and items. Each tested screen had no document-level horizontal overflow and no JavaScript page errors. The visual-capture step succeeded in [audit run 45210860088](https://github.com/Uli-Z/hausstandsliste/actions/runs/45210860088), despite a separate test-harness assertion stopping the overall browser suite.

**Limitations:** Screenshot review is not a physical-device, screenreader or real-user usability study. Other dialogs (event edits, advanced encrypted-file actions and PHP-only online management) were reviewed from their Svelte structures and existing browser interaction tests, rather than every possible state being photographed. Standalone and PHP builds must be distinguished when assessing save actions.

## Decision

The visual language is coherent, and the main navigation (Items, People, Money, Changes) makes sense. The app nevertheless asks people to process too many equal-priority cards, permanent controls and explanatory fragments. **Use progressive disclosure:** show the current result and the next primary action, and reveal calculation detail or exceptional maintenance actions only on request. Keep critical data-loss, plaintext-backup and permission warnings visible.

## Cross-cutting issues found in source and screenshots

1. **Avoid duplicate navigation and CTA placement:** header vs dashboard quick action; global Back vs in-detail breadcrumb; Save in header vs multiple backup actions.
2. **Help must help, not decorate.** On Save & share an orphan `?` appears on a separate line below the heading. Several 32 px question-mark triggers are smaller than a comfortable touch target. Move help immediately next to the relevant label; use >= 44 x 44 px interactive targets where possible. Rewrite unclear labels instead of adding more help icons.
3. **Accessibility:** current Svelte builds warn that interactive `role="dialog"` wrappers lack `tabindex` in DialogRouter, RedistributionDialog, EventEditDialog, ExecutedRedistributionEditDialog and SettlementDialog. Fix focus entry, Escape/focus restoration and keyboard navigation as a separate acceptance item, not only the warnings.
4. **Translation debt:** residual German literals remain in otherwise localized Svelte views and some German-formatted dates are used without locale selection. Review event text, mobile navigation labels, item details, transfer-mode labels and archive storage messages in both languages (Q13).
5. **Mobile density:** long group/app names truncate in the sticky header; four overview metrics and repeated action tiles push real content down. Keep the selected time-travel date legible whenever time travel is active, with no horizontal overflow.

## Recommended order and acceptance criteria

**First:** Q20 save/open/collaborate information architecture, then simplify Add item and Redistribution into task-focused defaults. **Second:** Q18 compact event history and removal of duplicate Back/CTA/empty-state panels. **Third:** Q17 contextual help/touch/focus audit and Q13 remaining DE/EN strings.

Accept changes only after testing 375 and 1280 px with real browser rendering, checking long labels and keyboard focus, ensuring exactly one unambiguous primary action per view, and rerunning manually requested cross-engine browser QA. Do not make heavy browser tests a per-commit GitHub Actions requirement.
